TFT-gogo 전적 검색 서비스

전략적 팀 전투(TFT) 유저가 소환사 전적을 검색하고 최근 매치, 증강, 덱 구성, 메타덱과 게임 가이드를 확인할 수 있는 서비스입니다. Spring Boot 백엔드, React 프론트엔드, FastAPI AI 서버를 모노레포로 구성하고 Riot API와 OpenAI API 연동 흐름을 함께 다루고 있습니다.

Java Spring Boot React MySQL FastAPI Docker

AI 활용 기록

AI를 기능이 아니라, 개발과 운영 전체에서 사용했습니다

제가 담당한 merged PR 120개를 본문·커밋·리뷰·댓글까지 확인해 AI 활용과 사람 검증 비중을 퍼센트로 정리했습니다. Lojipsa에서는 배포 후에도 AI가 스스로 자기 출력을 채점하는 피드백 루프를 직접 설계·운영하고 있습니다.

Claude Code Trace

96%

담당 PR 중 본문이나 커밋에 Claude Code 기반 작업 흔적이 남아 있는 비율입니다.

AI Review Linked

95%

담당 PR 중 CodeRabbit 리뷰, 요약, 코멘트가 연결되어 AI 리뷰 루프가 남아 있는 비율입니다.

Human Review Loop

79%

담당 PR 중 AI 리뷰와 별도로 사람 리뷰 또는 팀원 검토가 함께 남아 있는 비율입니다.

Verified Trace

93%

담당 PR 중 테스트, CI, audit, JMeter, 성능 수치처럼 검증 근거가 본문이나 커밋에 남은 비율입니다.

Harness Loop

Claude → Review → 검증
  • Claude Code로 구현 초안과 리팩터링 후보를 만들고 PR 단위로 쪼갰습니다.
  • CodeRabbit과 Codex 리뷰를 통해 회귀 위험, 누락된 테스트, 상태 불일치를 다시 점검했습니다.
  • 락, timeout, fallback, 인증처럼 운영 안정성에 걸리는 부분은 사람이 최종 판단했습니다.

Spec & Harness

AI를 쓰기 전에 기준을 먼저 고정했습니다

01 / Spec

먼저 스펙을 쪼갰습니다

기능을 바로 구현하지 않고 요청값, 응답 필드, 실패 응답, DB 상태 변화를 먼저 적었습니다. 이 기준을 Claude에 함께 전달해 AI가 임의로 구조를 바꾸거나 실패 케이스를 빠뜨리지 않게 했습니다.

API 계약 실패 응답 상태 전이

02 / Claude

Claude에는 역할과 제약을 줬습니다

/claude로 구현 범위, 수정 금지 영역, 테스트 명령을 함께 넘겼습니다. 단순히 코드를 생성시키는 것이 아니라, 정해진 스펙 안에서만 수정하도록 작업 환경을 만들었습니다.

작업 범위 수정 제약 테스트 명령

03 / Codex Review

Codex로 다시 검증했습니다

PR에서는 @codex 리뷰를 요청해 정상 동작보다 실패 경로, 동시 요청, 누락 테스트를 먼저 확인했습니다. 리뷰 후에는 같은 테스트 명령으로 재검증하고 빌드 성공 여부까지 확인한 뒤 병합했습니다.

PR 리뷰 실패 경로 재검증

02 / Issue & PR

이슈·PR 관리

작업 성격을 라벨로 나누고 PR과 이슈를 연결해 변경 이력을 남겼습니다.

03 / API & Integration

API 연동 범위 정리

Riot API, Community Dragon, FastAPI 추천 서버 연동 범위를 나눴습니다.

04 / Release

릴리즈 노트 관리

기능 추가, 버그 수정, 성능 개선 내용을 릴리즈 노트로 정리했습니다.

05 / Review Harness

AI 리뷰 검증

AI 리뷰로 병합 전 위험을 확인하고 수정 반영 여부를 재검토했습니다.
