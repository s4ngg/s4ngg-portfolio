AI Usage

AI를 기능이 아니라, 개발과 운영 전체에서 사용했습니다

프로젝트마다 AI를 쓴 방식이 달랐습니다. TFT-gogo에서는 담당 PR 120개를 분석해 개발 루프 안에서의 AI 활용을 퍼센트로 정리했고, Lojipsa에서는 배포 후에도 AI가 스스로 자기 출력을 채점하는 피드백 루프를 설계·운영했습니다. AllPick은 그 이전 시기 프로젝트로, AI가 개발 과정이 아니라 추천 기능 자체에 있었습니다. 아래 항목을 펼치면 프로젝트별로 실제 근거를 확인할 수 있습니다.

TFT-gogo

PR 단위 AI 활용 지표 — merged PR 120개 분석

Claude Code · CodeRabbit expand_more

담당한 merged PR 120개를 본문·커밋·리뷰·댓글까지 확인해 AI 활용과 사람 검증 비중을 퍼센트로 정리했습니다.

96%

AI Review Linked

95%

담당 PR 중 CodeRabbit 리뷰, 요약, 코멘트가 연결되어 AI 리뷰 루프가 남아 있는 비율입니다.

Human Review Loop

79%

담당 PR 중 AI 리뷰와 별도로 사람 리뷰 또는 팀원 검토가 함께 남아 있는 비율입니다.

Verified Trace

93%

담당 PR 중 테스트, CI, audit, JMeter, 성능 수치처럼 검증 근거가 본문이나 커밋에 남은 비율입니다.

Harness Loop

Claude → Review → 검증
  • Claude Code로 구현 초안과 리팩터링 후보를 만들고 PR 단위로 쪼갰습니다.
  • CodeRabbit과 Codex 리뷰를 통해 회귀 위험, 누락된 테스트, 상태 불일치를 다시 점검했습니다.
  • 락, timeout, fallback, 인증처럼 운영 안정성에 걸리는 부분은 사람이 최종 판단했습니다.

데이터 원칙

임의 데이터 미사용

환각 방지 설계

LLM-as-judge

매일 자동 채점

합성 시나리오로 핵심 기능을 매일 자동 실행하고, 다른 LLM 호출로 PASS/FAIL을 채점해 Slack에 보고합니다.

AllPick

이 프로젝트의 AI는 기능 안에 있었습니다

FastAPI · OpenAI API expand_more

AllPick은 Claude Code 같은 AI 코딩 도구를 개발 루프에 쓰기 이전 시기의 프로젝트입니다. merged PR 91개를 실제로 분석한 결과 PR 본문은 대부분 비어 있고 CodeRabbit 같은 AI 리뷰도 붙어 있지 않아서, 이 시기의 "AI 활용"은 개발 과정이 아니라 제품 기능 자체에 있었습니다.

제품 기능으로서의 AI

FastAPI + OpenAI API 추천 서버

관심 카테고리와 위시리스트를 바탕으로 FastAPI 추천 서버와 OpenAI API를 연동해, 사용자별 맞춤 상품을 추천하는 기능을 단독으로 설계·구현했습니다.

그 이후의 변화

개발 과정 자체에 AI를 결합

이후 TFT-gogo부터는 Claude Code와 AI 코드 리뷰를 개발 루프 안에서 쓰기 시작했고, Lojipsa에서는 배포 후 AI가 스스로 결과를 채점하는 LLM-as-judge까지 도입했습니다.
